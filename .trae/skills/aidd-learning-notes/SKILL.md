# AIDD 学习笔记整理

按照用户商定的分类体系和格式，整理 AIDD（AI辅助药物发现）学习过程中产生的内容。

## 核心原则

**先问后整理**：对话中出现了符合触发条件的内容，先问用户"这个值得整理一下，整理到 XX 里可以吗？"，用户同意后再动手。整理完告知用户写在了哪里。

**宁缺毋滥**：不够格的不硬塞，等攒够内容再写。用户说"这个不用记"就不记。

**不重复记录**：已经有的内容不重复写。同一个概念聊深了，在原文件基础上更新内容和"更新"日期，不新建文件。

**风格统一**：和现有笔记风格保持一致，用详细讲解式（有例子、有类比、有表格对比）。

**用户的学习日志不动**：`notes/learning_log.md` 完全是用户自己写的，不碰。

---

## 目录结构

```
notes/
  ├── learning_log.md          ← 用户自己写的，不动
  ├── problem_log.md           ← 报错记录，追加新内容
  ├── insights.md              ← 思考与感悟，按日期追加
  ├── faq.md                   ← 常见问答，按日期追加
  └── concepts/                ← 一个概念一个文件
        ├── README.md          ← 索引页（含 Mermaid 概念图）
        ├── early_stopping.md
        ├── xgb_parameters.md
        └── ...
```

## 触发条件

对话中出现以下内容时，自动整理：

### 1. 深入讨论了一个核心概念

讨论得比较成体系、有结构，不是一两句话能说清的。

**写哪里**：`notes/concepts/xxx.md`（新建文件）

**格式**：严格按照概念笔记模板（见下文）

**命名**：英文小写，下划线分隔，如 `cross_validation.md`

### 2. 用户问了一个好问题

有思考价值的、值得记录的疑问（不是简单的拼写错误那种）。

**写哪里**：`notes/faq.md`（追加条目）

**格式**：每条以 `### YYYY.MM.DD — 问题` 开头，下面写解答

### 3. 用户产生了深度思考

方法论、认知层面的感悟，不是具体知识点。

**写哪里**：`notes/insights.md`（追加条目）

**格式**：每条以 `## YYYY.MM.DD — 标题` 开头，下面写内容

### 4. 遇到并解决了有价值的报错

有教育意义的问题，不是简单拼写错误。

**写哪里**：`notes/problem_log.md`（追加条目）

**格式**：按原有风格：问题描述 → 原因 → 解决方案

### 5. 新遇到的技术词汇

对话中出现了新的重要英文技术词汇。

**写哪里**：`vocabulary.md`（追加到对应分类下）

**格式**：表格行：英文 | 中文 | 说明

### 6. 新增概念后同步更新

新建概念笔记后，同步更新：
- `concepts/README.md` 的 Mermaid 概念图和分类列表
- 相关概念笔记底部的"相关概念"链接（双向加）

---

## 不整理的内容

- 用户自己写的学习日志内容（不动 learning_log.md）
- Git 操作、仓库设置等琐碎操作
- 闲聊性质的内容
- 简单拼写错误、笔误类的报错
- 用户已经自己记录过的内容（不重复）
- 用户明确说"这个不用记"的内容

---

## 概念笔记模板

每个 `concepts/*.md` 文件统一结构：

```markdown
# 标题（中英文）

> 创建：YYYY.MM.DD
> 更新：YYYY.MM.DD

## 一句话总结
（用一句话说清楚是什么）

## 核心概念
（主要内容，分小节展开）

## 关键参数/属性
（有参数的话，列表或表格）

## 容易搞错的细节
（2-5个常见误区）

## 生活类比/直观理解
（帮助记忆的类比）

---

## 相关概念

- [概念名](文件名.md) — 一句话说明关系
- ...
```

日期格式：`YYYY.MM.DD`，如 `2026.09.28`。

---

## 交叉引用规则

每个概念笔记底部的"相关概念"：

- 至少 2 个，不超过 5 个
- 双向链接（A 链接了 B，B 也要链接 A）
- 每条后面加一句话说明关系
- 按相关程度排序，最相关的放前面

---

## 注意事项

1. 整理前先问用户是否同意，用户说可以再动手
2. 整理后告知用户写在了哪里
3. 用户对整理结果有意见时，随时调整
4. 拿不准要不要整理时，宁可先不整理，或者问一下用户
5. README.md 的 Mermaid 图要保持整洁，概念多了再调整布局
