## 模型与评估

### 2026.09.28 — 为什么评估函数只接收真实值和预测值，不内部处理数据？

因为"分离职责"的设计思想。评估函数的职责就是"给两个数组，算指标"，至于预测值怎么来的，它不管。

这么设计的好处：
1. **来源可能不同** — 预测值可能来自模型、来自论文表格、来自手工计算，不一定都是函数内部生成的
2. **预测步骤可能很复杂** — 标准化、降维、反对数变换… 每个项目不一样，函数写死就不灵活了
3. **可组合性强** — 同一个评估函数可以用在训练集、测试集、外部验证集上，只要传不同的 y_pred 就行

但也不是说一体化就不好。如果流程是固定的、重复的，一体化封装更方便。最好的策略是"两层设计"：底层小函数各管各的，上层再封装成一体化的工具。

### 2026.09.28 — XGBoost 的参数会互相影响吗？

会，而且影响很大。参数不是孤立的，牵一发而动全身。

最典型的几对：
- **learning_rate 和 n_estimators** — 学习率小需要更多树，学习率大需要更少树
- **max_depth 和正则化** — 树深了需要更强的刹车（正则化）
- **subsample 和 colsample_bytree** — 两个都增加随机性，效果叠加
- **max_depth 和 min_child_weight** — 都控制树复杂度，作用类似但角度不同

所以调参要有顺序：先调影响最大的（学习率 + 树数量），再调中等的（树深度、随机性），最后才碰正则化。不要一次调三个，你根本不知道是哪个起了作用。

### 2026.09.28 — 能不能算出最优的树的数量？

精确值算不出来，因为数据是高维的，损失函数形状是崎岖的，不是光滑的下坡。你不知道"目的地在哪"，只能走一步看一步。

但可以估个大概范围：

| 学习率 | 大概需要多少棵树 |
|--------|----------------|
| 0.3（大） | 几十 ~ 几百 |
| 0.1（中） | 几百 ~ 一千 |
| 0.05（小） | 一千 ~ 几千 |
| 0.01（很小） | 几千 ~ 上万 |

实际上不用算，设一个肯定够大的 n_estimators（如 1000），让早停自己找最佳点就行了。早停停在哪个位置，还能反过来指导你调学习率：停得太早（几十轮）说明学习率太大；停得太靠后（接近上限）说明学习率太小。

## 代码与设计

### 2026.09.28 — 分子指纹为什么要分两步创建数组（np.zeros + ConvertToNumpyArray）？

"先建空数组，再填数据"的模式，主要有三个好处：

1. **自己决定数据类型，省内存** — 你可以指定 dtype=np.int8（1 字节），而不是 RDKit 默认的 int64（8 字节），省 8 倍空间
2. **少一次内存拷贝** — 直接填你的数组，不经中间步骤，性能略好
3. **可以复用数组** — 不需要保存所有指纹时，同一个数组反复用，省内存

但如果需要保存所有指纹（要收集到列表里），第3个好处就用不上了。这是 RDKit 的 C++ 风格 API（调用者提供缓冲区），不是 Python 风格。

### 2026.09.28 — 函数内部为什么能访问外面的变量？

Python 函数的作用域查找顺序是：函数内部 → 外层 → 全局 → 内置。如果在函数内部找不到，就往外找。

所以函数里可以"读"全局变量，但不能直接"改"全局变量（改的话要用 global 关键字声明）。

虽然能读，但不推荐依赖全局变量——函数自给自足最好，不然把函数复制到别的地方，忘了把全局变量也复制过去，就报错了。

## 概念理解

### 2026.09.28 — Index 和普通列表有什么区别？

`df.columns` 是 Index 类型，不是普通列表。两者的区别是**设计目的不同**：

- **普通列表（list）** — 通用容器，什么都能装，擅长按位置取、追加、遍历
- **Index** — 专门存标签/索引的加强版列表，查找速度快（哈希查找）、支持自动对齐、可以强制唯一

简单说：list 是"通用的书包"，Index 是"专门的文件柜"——都是装东西的，但设计目的不同，擅长的事情也不同。

日常使用时感觉差别不大，知道有这么个东西就行。

### 2026.09.28 — axis=0 和 axis=1 怎么记？

- **axis=0** = 竖着（沿行的方向压缩），行被压没了，列保留 → 每列一个结果
- **axis=1** = 横着（沿列的方向压缩），列被压没了，行保留 → 每行一个结果

记忆口诀：**1 是横（一），0 是竖（丨）**。

或者看形状变化：3 行 4 列的矩阵，sum(axis=1) 后变成 3 个值（行数不变，列数没了）。

## 仓库与 Git

### 2026.09.28 — 私有仓库转公开后还能转回去吗？

可以，随时能来回转，没有次数限制。在仓库 Settings → General → Danger Zone 里改。

但要注意：公开期间如果有人 fork 了你的仓库，即使你后来转私有了，别人 fork 出去的那份还是公开的。不过学习笔记类仓库基本不会有人 fork，不用担心。
