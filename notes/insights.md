## 2026.09.28 — 分子指纹是近似，不是真相

分子指纹把三维的、动态的、有电子云的真实分子，压扁成一串 0 和 1。丢的信息很多（三维结构、手性、顺反异构…），但关键是：丢的信息对当前任务影响有多大？如果 80% 的信息够用，那 20% 的失真可以接受。

这不只是分子指纹的问题——所有模型都是这样。牛顿力学不是"真的"（相对论更接近），但造桥造火箭够用了。原子模型从实心球到行星模型到电子云，每次都是"更接近"，但没人敢说"就是真相"。

**模型的价值不在于"真不真"，而在于"准不准"。** 只要在特定的问题上预测得准，它就是有用的。

这也是为什么药物发现里有那么多种分子表示方法（描述符、指纹、药效团、对接、GNN…）——没有一种是"最真实的"，每种都是在某些场景下够用。

## 2026.09.28 — 分工不同，设计目的不同

不同的数据结构（list vs Index）、不同的函数设计（一体化 vs 分离职责），没有绝对的"好坏"，只有"适不适合"。

- list 是通用容器，什么都能装
- Index 是专门存索引的，查找快

- 一体化封装适合固定流程，用起来方便
- 分离职责适合多变的场景，灵活可组合

**本质区别在于分工不同、设计目的不同。** 理解了"这个东西是为什么场景设计的"，就理解了它的特点，而不用死记硬背。

这个思路可以推广到几乎所有技术概念——不要问"哪个更好"，要问"哪个更适合我现在的场景"。

## 2026.09.28 — 边学边写日志，比事后回忆强太多

学一点、想一点、写一点，比"先看完一整章再做笔记"有效得多。

原因：
1. 想法是转瞬即逝的，触发点过去了就写不出来了
2. 边学边写等于立刻检验自己懂没懂，避免"我懂了"的幻觉
3. 记录真实的学习路径（绕弯路、踩坑、顿悟），比事后整理的"正确答案式"笔记更有价值

费曼学习法的自然形态就是这样——学一点、跟自己讲一遍、写下来。

## 2026.09.28 — 刨根问底不是浪费时间

搞清楚每个概念"为什么这么设计""和那个有什么关系""本质区别是什么"，比多跑通十个脚本还值钱。

跑通脚本谁都行，但能把每个概念的关系都理清楚的人不多。到后期拼的不是记住多少函数名，而是脑子里有没有清晰的知识框架。

"不问清楚就不痛快"这种性格，做技术是优势。

## 2026.09.29 — 与 AI 协作的方法论

### 核心问题

用 AI 生成代码，自己不写，能学会吗？会虚浮吗？能力能积累吗？

### 角色定位

- **你是架构师**：定方向、做决策、把关结果
- **AI 是执行者**：写模板代码、跑流程、查资料、排查报错

### 代码分类

| 类型 | 举例 | 谁来写 |
|------|------|--------|
| 模板代码 | 文件读写、API调用、画图框架 | AI写，你能看懂 |
| 核心逻辑 | 阈值定多少、用什么特征、选什么模型、怎么评估 | 你定，AI执行 |
| 语言基础 | if/for/函数定义/pandas数据处理 | 你必须会写 |

### 能力分层

| 能力 | 要求 | 检验标准 |
|------|------|---------|
| 能看懂 | 每行代码知道在干什么 | 给你代码你能逐行讲 |
| 能改 | 能改参数、改路径、改逻辑 | 换个靶点你知道改哪里 |
| 能判断 | 结果对不对你有感觉 | 准确率95%你能说清是好还是有问题 |
| 能默写 | 不做要求 | 查文档写出来就算会 |

### 阶段性演进

```
第1个项目（EGFR）→ AI写，你读，学结构
第2个项目（COX-2）→ 你写核心逻辑，AI写模板
第3个项目（DPP-4）→ 你写大部分，AI只查bug
第4个项目开始 → 你独立写，AI只当字典
```

### 防错意识

AI会犯三类错，你必须防：
1. **逻辑错误**：代码跑通但结果错了 → 靠"能判断"防
2. **参数不当**：参数不合理 → 靠"能看懂"防
3. **知识错误**：用错指标用错方法 → 靠"能判断"防

最后一道防线永远是你，不是AI。

### 不可量化能力的积累

架构设计、模型选择、特征选择、结果判断——这些能力靠四件事：

1. **每个决策都问"为什么"**：AI每次做决策时告诉你理由，记住的是理由不是结论
2. **同一件事做两遍对比**：用指纹 vs 用描述符，对比结果差多少、为什么
3. **犯错然后记住**：设错阈值 → 看到结果变差 → 理解阈值的影响
4. **读别人的代码和论文**：跟自己的做法对比，谁的对

### 检验方法

每做完一个项目，问自己三个问题：
1. 关掉AI，我能从零写一个同类项目吗？
2. 项目再大三倍，我知道怎么扩展结构吗？
3. 换个靶点，我知道改哪里吗？

### 函数名记不住不要紧

知道做什么、知道结果对不对，这就是会。函数名记不住是肌肉记忆的事，不是能力问题。查文档写出来和默写出来，没有本质区别。做得多了自然就记住了。

### 虚浮感的本质

觉得虚浮不是因为没用AI，是因为看得多、跑得少。跑代码、报错、自己改——这个过程重复十几次，虚浮感就消失了。

## 2026.10.11 — 模型学的是化学型，不是机制

COX-2 项目做完，跟 EGFR 项目放在一起对比，撞出了这个比任何单个指标都重要的事实。

### 证据一：错误样本长着"同族的脸"

看 RF+指纹模型（随机划分）测试集的 47 个假阳性、31 个假阴性：

- **假阳性**：一大半是"二芳基杂环 + 磺酰胺/甲砜 + 氟苯"结构——这就是塞来昔布（celecoxib）的脸。模型看到这张脸就投活性票，哪怕这个具体分子并不活跃。
- **假阴性**：混着 profen 类（布洛芬同款）羧酸结构——训练集里这类骨架样本少，模型没认过几张"profen 脸"，于是漏判。

模型不是在理解"这个分子为什么抑制 COX-2"（side pocket、Val523 那套机制），它只是在数子结构：训练集见过的脸 → 活性；没见过的 → 非活性。

### 证据二：换掉测试集的骨架，成绩立刻现形

RF+指纹模型，随机划分 vs 骨架划分：

- COX-2：AUC 0.844 → 0.657，**掉了 0.18**
- EGFR：同样操作只掉 0.07（骨架划分仍有 0.838）

随机划分时训练集和测试集共享大量同骨架分子，模型靠"认脸"就能拿分。骨架划分把同族骨架整体挪进测试集，模型必须泛化到没见过的骨架——COX-2 立刻露馅。

为什么 EGFR 掉得少？EGFR 抑制剂骨架集中（喹唑啉家族），学到的子结构模式跨分子可迁移；COX-2 抑制剂是昔布类、profen 类、水杨酸类多化学型并存，某张"脸"跨化学型不通用。

### 证据三：骨架划分下，描述符反超指纹

COX-2 骨架划分：描述符 AUC 0.720 > 指纹 AUC 0.649。

随机划分下指纹总是更强，为什么一换划分就反转？描述符（MW、LogP、TPSA…）是整体理化性质，跨化学型还能大致迁移；指纹是特定子结构，只在训练集见过的化学型里有效。**模型靠子结构记忆得分时，指纹显得很强；一旦要求真泛化，"记忆"就现出原形。**

### 这句话到底在说什么

**QSAR 模型的本质：在训练数据出现过的化学骨架里，记住"哪些子结构模式和活性标签相关"。** 它没有药物化学家的因果推理，回答不了"为什么"，对全新骨架的外推能力很差。

这不推翻模型的价值——回到 09.28 那条"指纹是近似不是真相"：模型的价值在"准"不在"真"。但使用边界要刻在脑子里：

1. **别对新化学型报太高期望**——模型最擅长的是优化已知骨架系列（lead optimization），不是从头找新骨架
2. **别把模型判断当机制解释**——"模型说它活性" ≠ "它通过 XX 机制起效"，模型会犯"昔布脸"错误
3. **化学型覆盖比样本量更根本**——数据集里化学型的多样性决定模型能力的天花板

### 顺带发现的副产品：组间区分力 ≠ 组内区分力

HBD 在 EGFR vs COX-2 **两组之间**差异最大（效应量 0.682——EGFR 抑制剂要 hinge 区氢键给体，COX-2 主要靠疏水作用），但在 COX-2 数据集**内部**做活性/非活性区分时重要性垫底——大家均值都只有 0.74 个给体，谁也区分不开谁。

"这个特征能区分两个靶点的数据集"和"这个特征能预测某靶点里的活性"是两回事。前者反映结合模式差异，后者才是建模有用的信号。看组间对比图看得很爽的特征，进了模型可能毫无用武之地。

## 2026.10.14 — 领域不缺算法，缺验证

CSBJ 2021 那篇 ML-in-drug-discovery 综述读完（3.1 逐句费曼过，之后框架式扫完全文）。最大的收获不是记住了哪个模型，而是拿到了一张**地图**——以后看到任何新方法、新论文，都能定位到它站在图上的哪个格子。

### 应用层：ML 在药发里能干什么（六个格子）

| 格子 | 干什么 | 现状 |
|---|---|---|
| 活性预测 | 给定靶点 + 化合物，预测它多强 | 成熟，COX-2 项目就在这 |
| 靶点预测 | 给定化合物，预测它打哪个靶点 | 较成熟（老药新用） |
| 性质 / ADMET | 分子自己成不成药（溶解度、代谢、毒性） | 部分成熟，数据噪声大 |
| 虚拟筛选 | 把活性预测规模化，给百万级化合物库排序 | 成熟，标准流程 |
| 分子生成 | 按需求造新分子 | 能生成，但卡在下一格 |
| 合成可行性 | 生成的分子造得出来吗 | 生成式的死穴，远未解决 |

生成 → 活性 → 可合成是一条流水线；综述的判断是前两环快、第三环拖后腿。

### 技术栈：怎么干（三层）

- **表示层**：描述符（少而精、可解释）vs 指纹（多而全、bit string）。核心矛盾就是 3.1 那套——**特征数 = 未知数**，维度选择是在钢丝上走
- **模型层**：线性 → 树 → SVM → 神经网络，是"可解释 → 黑箱"的单向牺牲
- **验证层**：划分方式、适用域、baseline——决定模型是真是假的那一层

### 地基与裂缝

- **地基**：相似性假设——结构相似则活性相似
- **裂缝**：activity cliff——结构微改活性剧变，假设失效点
- **高维欠定**：p > n 时无穷多满分解，"背答案"风险；四个解法（加数据 / 减特征 / 正则化 / 测试集）介入位置分别是训练前、损失函数里、训练后
- **一句话**：保证永远来自数据之外——更多的现实、更少的自由度、一条挑选规则、一个裁判

### 三面墙（综述自己承认还没解决的）

| 位置 | 墙 |
|---|---|
| 数据侧 | 实验噪声大且不均、公开数据只是冰山一角、明星靶点偏倚 |
| 模型侧 | 黑箱不可解释；生成物不管能不能合成 |
| 验证侧 | 适用域问题；文献性能普遍虚高（随机划分 vs 骨架划分）；计算预测到临床有效之间的鸿沟 |

**验证侧是最薄的一环。** 这是整篇综述对我最有价值的一句：这个领域不缺算法，缺的是让算法在真实数据上可靠工作的工程和验证方法。

### 时间维度：CADD → AIDD 是延续，不是革命

看完全文最大的感受：AIDD 的前身 CADD 早就开始了，很多方法的底层理论是上个世纪的（贝叶斯 1763、Hansch 线性 QSAR 1960s、RF/SVM 1980-90s）。**算法从来不缺——缺的是数据量和算力到位之后，把老算法真正跑通的条件，以及跑通之后诚实评估它的方法。** 这直接决定选题取向：纯换算法不是好选题，真正的机会在"老方法在新问题规模下暴露的局限"。

### 我的站位

- **已踩的格子**：活性预测 + 验证侧工程——COX-2 项目第五步（骨架划分、昔布脸分析）恰好落在综述认为最稀缺、最重要的验证侧
- **未踩的格子**：ADMET、分子生成、逆合成
- 结合 13 周计划的切口（口服药 ADMET 成药性），下一个要踩的格子几乎是安排好的
