# 数据清洗 (Data Cleaning)

> 创建：2026.09.29
> 更新：2026.09.30

## 一句话总结

把从数据库拉来的"脏数据"（有缺失、有重复、格式不统一）收拾干净，变成模型能直接用的高质量数据集。**Garbage in, garbage out**——数据质量决定模型上限。

---

## 核心概念

### 为什么要做数据清洗

ChEMBL 等公开数据库里的数据虽然权威，但都是"原始状态"：

- 有些数据缺 SMILES（连分子结构都没有）
- 有些数据缺活性数值（测了但没报具体结果）
- 同一个分子有多种 SMILES 写法（盐型、互变异构、电荷状态不同）
- 同一个分子被不同实验室测了好几次，数值不完全一样
- 有些活性是"大于/小于"的范围值，不是精确值

这些问题不解决，模型学不到真实的分子-活性关系，反而会学到数据里的"混乱"。

### 清洗的标准流程（QSAR 项目）

以 EGFR 项目为例，5000 条原始数据经过清洗后剩下 2032 个唯一分子：

```
原始数据 5000 条
  │
  ├→ 去掉空 SMILES → 5000 条
  │
  ├→ 去掉空 pChEMBL → 3131 条   ← 砍掉最多！
  │
  ├→ 只保留精确值（=） → 3131 条
  │
  ├→ SMILES 标准化 → 3131 条
  │
  ├→ 去重（取平均值） → 2032 个唯一分子
  │
  └→ 定义活性标签 → 1054 活性 : 978 非活性
```

---

## 每一步在做什么、为什么做

### 1. 去掉空 SMILES

```python
df = df.dropna(subset=['smiles'])
```

**做了什么**：删除没有分子结构的记录。

**为什么**：没有 SMILES 就没法计算描述符和指纹，模型"看不见"这个分子。没有结构的活性数据毫无意义。

**丢多少**：取决于数据质量，ChEMBL 一般丢得很少。

### 2. 去掉空 pChEMBL

```python
df = df.dropna(subset=['pchembl_value'])
```

**做了什么**：删除没有活性数值的记录。

**为什么**：pChEMBL 是监督学习的"标准答案"（标签）。没有答案，模型无从学起。

**丢多少**：这步通常丢得最多！很多活性数据只有定性描述（"有活性"/"无活性"），没有具体数值。EGFR 数据从 5000 掉到 3131，就是因为有近 2000 条没有 pChEMBL 值。

### 3. 只保留精确值（standard_relation == '='）

```python
df = df[df['standard_relation'] == '=']
```

**做了什么**：只保留活性数值是"等于"的记录，扔掉 `>` 和 `<`。

**为什么**：ChEMBL 里的活性数据有三种关系：

| 符号 | 含义 | 例子 | 能不能用 |
|------|------|------|---------|
| `=` | 精确值 | IC50 = 10 nM | ✅ 可以直接用 |
| `>` | 大于检测下限 | IC50 > 10 μM | ❌ 只知道"不好"，不知道多不好 |
| `<` | 小于检测上限 | IC50 < 1 nM | ❌ 只知道"很好"，不知道多好 |

`>` 和 `<` 都是**删失数据**（censored data），精确值不知道，只有范围。新手阶段先用 `=` 的最稳妥。进阶后可以用特殊方法（如 cox 模型）处理删失数据。

### 4. SMILES 标准化（最关键的一步）

```python
def standardize_smiles(smiles):
    mol = Chem.MolFromSmiles(smiles)
    mol = normalizer.normalize(mol)      # 归一化：电荷、官能团表示
    mol = lfc.choose(mol)                # 取最大片段：去掉盐、溶剂
    mol = te.Canonicalize(mol)           # 统一互变异构形式
    return Chem.MolToSmiles(mol)
```

**做了什么**：把同一个分子的不同 SMILES 写法统一成一种标准形式。

**为什么**：这是药物化学数据里最大的坑——**同一个分子，可以有很多种 SMILES 写法**：

| 问题 | 说明 | 例子 |
|------|------|------|
| **盐型不同** | 分子带了不同的盐（盐酸盐、钠盐等） | 阿司匹林 vs 阿司匹林钠 |
| **互变异构** | 酮式/烯醇式、酰胺/亚胺醇等 | 同一个分子的不同质子排布 |
| **电荷状态** | 不同 pH 下的质子化状态不同 | 氨基在酸性条件下带正电 |
| **立体化学写法** | 手性中心的表示方式可能不同 | R/S 标记方式不一致 |

如果不标准化，后面去重的时候，**明明是同一个分子，却会被当成不同分子**，数据就虚高了。

> 你看到的 `Tautomer enumeration stopped at 156 tautomers` 警告是正常的。RDKit 在枚举互变异构体时到了上限，但还是选出了规范形式，不影响结果。

### 5. 去重（同一个分子多条记录取平均）

```python
df_agg = df.groupby('standard_smiles').agg({
    'pchembl_value': 'mean',   # 活性取平均
    ...
}).reset_index()
```

**做了什么**：同一个分子如果有多条活性数据，取平均值。

**为什么**：ChEMBL 里同一个分子可能被不同实验室、用不同实验方法测了好几次，数值不完全一样。怎么处理这些重复测量？

| 方法 | 做法 | 适用场景 |
|------|------|---------|
| **取平均** | 多次测量取均值 | 最常用，假设各次测量同等可信 |
| **取中位数** | 取中间值 | 更稳健，不受极端值影响 |
| **取最大值** | 取最好的 | 最乐观估计，偏冒险 |
| **取最小值** | 取最差的 | 最保守估计 |

我们用的是**平均值**，属于比较中庸、最常用的做法。

**丢多少**：EGFR 数据从 3131 条掉到 2032 个唯一分子，说明有 1100 条是重复的！这也说明了 SMILES 标准化有多重要——不标准化的话，这些重复根本发现不了。

### 6. 定义活性标签

```python
df_agg['label'] = (df_agg['pchembl_value'] >= ACTIVE_THRESHOLD).astype(int)
```

**做了什么**：把连续的 pChEMBL 值转换成 0/1 二分类标签。

**为什么**：分类任务需要明确的"是/否"答案。需要一条分界线来区分"活性"和"非活性"。

**阈值怎么选**：

| 阈值 | 对应 IC50 | 严格程度 |
|------|-----------|---------|
| pChEMBL ≥ 6.0 | IC50 ≤ 1 μM | 宽松（常用最低标准） |
| **pChEMBL ≥ 6.5** | **IC50 ≤ 316 nM** | **中等（最常用）** |
| pChEMBL ≥ 7.0 | IC50 ≤ 100 nM | 严格 |

我们用的是 **6.5**，这是药物化学里比较常用的阈值。

**正负样本比例**：EGFR 数据是 1054 : 978 ≈ 1:1，非常均衡。这对分类模型是好事——不会偏向多数类。如果比例很悬殊（比如 9:1），就需要考虑过采样、欠采样或调整 class_weight。

## 容易搞错的细节

### 1. 去重必须在标准化之后

先标准化 SMILES 再去重，否则同一个分子的不同写法会被当成不同分子。

### 2. "精确值"也不是绝对精确

`standard_relation == '='` 只代表实验报告了一个具体数值，但实验本身有误差。不同实验室测同一个分子，数值可能差 2~3 倍都是正常的。

### 3. 正负样本不均衡时怎么办

如果活性/非活性比例差很多（比如 1:9），不要简单地"删点数据凑平衡"。更合理的做法：
- 用 `class_weight` 调整损失函数权重
- 用 AUC-ROC 代替准确率做评估指标
- SMOTE 过采样（但容易过拟合，慎用）

### 4. 清洗不是丢数据越多越好

每一步丢数据都是在**牺牲样本量换取数据质量**。如果数据本来就少，有些步骤可以放宽标准（比如保留 `>` 的数据做删失回归）。

### 5. 标准化不是越快越好

SMILES 标准化是清洗步骤里最慢的一步（尤其是互变异构枚举），但这步最值得花时间——省了这步，后面所有分析都建立在"沙子上"。

### 6. 互变异构统一是妥协，不是"没有影响"

这是最容易产生误解的一步。**互变异构体确实是不同的化学实体**——质子位置不同，导致分子指纹、疏水性、静电性质、pKa 甚至空间构型都可能不同。把它们统一成一种形式，确实会丢失信息。

那为什么还要统一？因为这里存在一个**根本矛盾**：

| 目的 | 需要 | 矛盾 |
|------|------|------|
| **去重** | 同一分子的不同互变异构体必须识别为"同一个分子" | 否则数据膨胀，大量重复 |
| **性质预测** | 不同互变异构体应该分开对待 | 因为它们性质不同 |

统一互变异构是**数据清洗阶段为了去重而做的妥协**，不是因为它"没有影响"。

**实际项目里的几种策略**：

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **规范统一** | 用 `Canonicalize()` 选一个规范形式 | 简单、去重方便 | 丢失异构体间的性质差异 |
| **选最稳定形式** | 枚举后按能量/丰度选一个 | 比规范统一稍好 | "最稳定"不一定好算 |
| **全部保留** | 不统一，每个异构体作为独立样本 | 保留性质差异 | 数据膨胀、可能数据泄漏 |
| **用不变指纹** | 用 3D 描述符或互变异构不变指纹 | 最严谨 | 复杂度高得多 |

**什么时候需要更谨慎？**
- 预测 pKa、溶解度等对质子化状态敏感的性质
- 分子含有多个互变异构位点（如四氮唑、苯并咪唑）
- 对结果精度要求高的发表级研究

**什么时候规范统一够用？**
- 初步 QSAR 模型（Morgan 指纹 + MW/LogP 等粗粒度描述符）
- 数据量大、互变异构体占比小
- 学习阶段的项目

## 生活类比

数据清洗就像**买菜做饭前的备菜**：

- 去掉空 SMILES → 把烂叶子、坏的扔掉
- 去掉空 pChEMBL → 把没标价的菜放回去（不知道多少钱没法算账）
- 只保留精确值 → 只买明码标价的，不买"大概这个价"的
- SMILES 标准化 → 把同一种菜的不同叫法统一（"西红柿"和"番茄"都是一个东西）
- 去重取平均 → 同一个菜问了好几个摊位，取个平均价
- 定义活性标签 → 按价格分成"贵的"和"便宜的"两堆

备菜花时间，但不备好菜，炒出来的菜就没法吃。
