# 骨架划分 Scaffold Decomposition

> 创建：2026.09.28
> 更新：2026.09.28

## 一句话总结

把分子的"躯干"和"四肢"分开——保留核心的环结构和连接环的桥，砍掉挂在边上的小基团，得到分子的骨架。

---

## 核心概念

### 基本思想

药物分子可以分成两部分：

- **骨架（Scaffold）**：核心结构，决定了分子"属于哪一类"
- **侧链（Side chain / R-group）**：挂在骨架上的小基团，用来微调活性和性质

就像人一样：骨架是骨头架子（每个人都差不多），肉和衣服是侧链（每个人不一样）。

### 为什么要做骨架划分？

因为药物的**核心活性通常由骨架决定**，侧链是在骨架基础上做优化的。

举个例子：
- 阿司匹林、布洛芬、萘普生——长得不一样，但都是非甾体抗炎药（NSAID）
- 它们有相似的骨架特征，只是侧链不同
- 骨架决定了"这类药治什么"，侧链决定了"哪个效果更好、副作用更小"

### Bemis-Murcko 骨架（最经典的算法）

RDKit 里默认用的就是这个。划分规则很简单：

1. **所有的环都保留**（苯环、哌啶环、嘧啶环等）
2. **连接环之间的链保留**（两个环之间的桥，比如 -CH2-、-NH-、-CO-）
3. **端基全部砍掉**（只连在一个原子上的基团，比如甲基 -CH3、羟基 -OH、氯原子 -Cl）

```
原始分子（阿司匹林）：

      O
      ||
  CH3-C-O-苯环-COOH

Bemis-Murcko 骨架：

      O
      ||
  H-O-C-苯环-COOH？不，不对

正确的骨架（只保留环和环之间的连接）：

  苯环  ← 只有苯环，因为阿司匹林只有一个环
```

> 阿司匹林只有一个苯环，所以它的骨架就是苯环本身。有两个以上环的分子，骨架才会更有意义。

---

## 关键参数/属性

| 方法 | 说明 | RDKit 函数 |
|------|------|-----------|
| Bemis-Murcko 骨架 | 最常用，保留环+连环的链 | `MurckoScaffold.GetScaffoldForMol(mol)` |
| 通用骨架（Generic） | 把原子换成"任何原子"，键换成"任何键"，更抽象 | `MurckoScaffold.MakeScaffoldGeneric(scaffold)` |
| 骨架 SMILES | 骨架的文本表示 | `Chem.MolToSmiles(scaffold)` |

通用骨架的意思是：不在乎具体是碳还是氮，单键还是双键，只关心"拓扑形状"。比如苯环和吡啶环，在通用骨架眼里都是"六元环"。

## 容易搞错的细节

### 1. 骨架没有唯一的"标准答案"

不同的划分算法得到的骨架不一样，没有哪个是"对的"，哪个是"错的"。Bemis-Murcko 只是最常用的一种。

### 2. 单环分子的骨架就是那个环本身

如果分子只有一个苯环，那骨架就是苯环。听起来很废话，但事实就是这样——骨架划分对多环分子更有意义。

### 3. 骨架不一定是"最有活性的部分"

骨架划分是纯结构规则，不考虑活性。有时候活性关键位点反而在侧链上，骨架只是个"架子"。

### 4. 骨架跃迁不等于骨架相似

骨架跃迁（Scaffold Hopping）是找"活性相似但骨架完全不同"的分子，恰恰是为了跳出现有骨架的限制。

---

## 有什么用

| 用途 | 说明 |
|------|------|
| **SAR 分析** | 把同骨架的化合物放一起，看哪些侧链改变了活性 |
| **骨架跃迁** | 找到活性相似但骨架不同的分子，突破专利限制 |
| **数据集多样性评估** | 看数据集中有多少种不同骨架，是不是都集中在几种骨架上 |
| **骨架拆分验证** | 测试集用训练集没有的骨架，验证模型的真实泛化能力 |
| **聚类分析** | 按骨架给分子分组，研究各类的性质差异 |

## 生活类比/直观理解

骨架划分就像**识别汽车的车型**：

- 骨架 = 车型（轿车、SUV、卡车）
- 侧链 = 颜色、轮毂、内饰、天窗、贴膜

同一款车型（骨架），可以有不同的配置（侧链）。
不同车型（不同骨架），就算都是四个轮子，也不是一类。

药物化学家做先导化合物优化，就像在同一款车型上改配置——车型不变，把内饰从布座椅换成真皮座椅，加个天窗，换个音响。而骨架跃迁是换一款车型。
